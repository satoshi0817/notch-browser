# Yoinkの操作調査とファイル棚への反映

調査日: 2026-09-29。Mac版を対象とし、iOS版の仕様は混ぜない。公式製品情報・Usage Tips・リリース履歴を確認した。インストール済みYoinkは3.7.6だったが、このセッションから同アプリのUIを取得できず、競合の実機操作を完了したとは扱っていない。

## 調査から採用した操作

[公式のスタック説明](https://blog.eternalstorms.at/2019/04/)では、一度に追加した複数ファイルを一組にし、まとめて取り出したり分解したりする。今回の棚も、ドロップ単位のスタックを基本にした。

[Mac版Usage Tips](https://eternalstorms.at/yoink/mac/tips/)は、ロックした項目の保持、直前に取り出した／除いた項目の復元、右クリックでのFinder表示、クリップボードからの追加などを説明している。これらを棚の整理・受け渡し操作として採用した。

[3.7の更新情報](https://updates.eternalstorms.at/notes/YNKMC/3.7)には、ファイルを置いたのに隠れる不具合、ドロップしなかった時の表示復帰、画面変更、再起動後の参照、ウィンドウの自動サイズに関する修正がある。機能の有無だけでなく、保持と表示の状態遷移を検証対象にした。

[3.7.6の更新情報](https://updates.eternalstorms.at/notes/YNKMC/)でも、取り出しの信頼性とブラウザごとの互換性が改善されている。見た目の類似だけで受け渡し互換性を保証せず、実際のAppKitドラッグセッションで複数ファイルを検証した。

## 今回の対応表

| 操作 | NotchBrowserでの動作 |
|---|---|
| ファイルを置いてマウスを離す | ファイルがある棚は開いたまま。ブラウザ表示中なら、ブラウザだけ閉じて小型の棚を残す |
| 再起動 | 保存済みの項目とスタックを復元して棚を開く |
| 2つ以上を同時に追加 | 「2ファイル」等の1スタックで表示。別のドロップは別のまとまりになる |
| 同じファイルを再追加 | 重複を増やさず、そのドロップの他のファイルとまとめる |
| スタックをドラッグ | 中の各ファイルを独立したファイルURLとして一度に渡す。ZIPや仮フォルダには変換しない |
| スタックの一部を操作 | 矢印／ダブルクリックで展開し、子ファイルを個別に選択。Cmd／Shiftの複数選択も可能 |
| まとめ直す／分解 | 右クリックメニューから選択ファイルをスタック化、スタックを単独項目へ分解 |
| 一部をクリア | 「選択をクリア」、Delete、右クリック。親スタックなら一組全体、子項目ならそのファイルのみ |
| 全件クリア | 文字付きの「すべてクリア」。ピン留めを含む全参照を外す。ピン留め以外だけを外す操作も別に残す |
| 取り消す | 「クリアを戻す」で直前のクリア／成功した取り出しを復元。順序とスタックも復元する。履歴は今回の起動中の直前1回 |
| 取り出しに成功 | 初期設定では棚から外す。ピン留めしたファイルは残す。設定で取り出し後も残せる |
| 取り出しを取消／受信先が拒否 | 項目を残す。失敗したドラッグでファイルを消さない |
| 一時的に隠す | 明示的な閉じる操作では隠せる。データは保持し、メニューから開き直せる |
| 表示サイズ | 項目数に応じて高さを調整。上限を超えたらスクロール |
| プレビュー／Finder表示 | Space／目のボタン、右クリック。ファイルのダブルクリックは開く、Cmd＋ダブルクリックはFinder表示 |
| キーボード | 棚にフォーカスがある時はCmd+A/C/V/ZとDeleteを棚に適用し、ブラウザの操作と競合させない |

## 差分・対象外

元ファイルを移動・削除せず、取り出しはコピーとして提供する。「棚からクリア」と「元ファイルをゴミ箱へ入れる」は別の操作で、後者は実装しない。ピン留めは自動取り出し後の保持に使い、明示的な全件クリアを妨げない。

今回の対象はファイル棚の操作。YoinkのHandoff、Continuity Camera、クリップボード履歴、macOS Services、F5長押し／二度押し、fnによる一時切替、カーソル位置への浮遊表示までの再現は含めない。ノッチの形とSF Symbolsの統一を維持する。

生成ファイルのpromise受信、Mail・各ブラウザなど全アプリでの互換性、Finder同等の強制移動は引き続き対象外。ファイルが見つからないスタックは、一部だけを黙って取り出すのではなく、取り出しを開始しない。

## 検証

- macOS 15.7.9で30件の自動テストを実行。スタック永続化、旧データ移行、再ドロップ時の重複防止、親子同時選択の重複排除、一部クリア・復元・順序、ピン留め保持、空／非空の表示遷移を確認。
- 別bundle IDのAppKit検証用ウィンドウから2ファイルを実際に同時ドロップし、1スタックとして表示されることを確認。
- 1スタックをドラッグし、受信ウィンドウ側で2つの独立したファイルURLを受け取ったことを保存結果で確認。成功後に棚の参照が0件になることも確認。
- マウスを外してもファイル入りの棚が開いたままであること、展開した子の片方をクリアするともう片方だけが残ること、全クリアで0件になり復元できることを画面・保存データで確認。
- 当初のNSTableViewの行ドラッグでは、1行から複数のpasteboard項目を出すとAppKitが拒否したため、ファイルごとにNSDraggingItemを作るドラッグセッションへ修正して再検証した。
- 競合Yoinkの全機能再現、全アプリとの受け渡し、複数の実ディスプレイでの操作、Intel／macOS 26上での実行は未検証。
